## 一·五、论文模板实测结论

来源：`/Users/jason/Downloads/论文模板260909.pdf`（3 页 A4，595×842pt）

### PDF 的 3 页是纸张物理换页，不是语义切分

证据明确：

- 第 2 页开头「其中，上下标表示变量时用斜体」直接续第 1 页末尾「变量可用单个字母或单个字母带上下标表示」，**句子跨页连续**。
- 「参考文献」的 11 条格式说明从第 2 页下半排到第 3 页，**同一份列表被物理切断**。
- 分页点落在内容中间，无任何语义依据。

结论：**网页不应模仿 PDF 的物理分页。** 这正是上一轮删掉的固定纸页分页方案。

### 模板本身是双栏

实测第 2 页逐行坐标，同一 y 上存在两条并行正文流：

```

右栏 x0=308.2 → x1≈540   栏宽 231pt
页面宽 595pt，栏宽比 ≈ 39%
```

当前实现 `#journalPaper` 宽 920px、栏宽 396px，栏宽比 43%。
**双栏方向正确，无需改成单栏。**

### 与模板的真实差异（三条）

1. **行距偏松**。模板 10.4pt 字号配 14.2pt 行距 = **1.37 倍**；当前 **1.7 倍**，松 24%。
2. **刊头信息缺失**。模板有卷号、期号、DOI 行、中图分类号/文献标识码/文章编号；
   当前刊头只有 logo + 年月 + 期号。
3. **英文摘要区块缺失**。模板末尾有 English Title（三号加粗）、Abstract、Key words；当前没有。

## 方案 A：按章拆成独立 URL

### 效果

```
/post/er-ruan-jian-jia-gou/           ← 封面自动跳第一章，或目录页
/post/er-ruan-jian-jia-gou/1-yin-zi.html
/post/er-ruan-jian-jia-gou/2-san-wen.html
...
```

每页页脚：`← 上一章 · 目录 · 下一章 →`

### 需要改的地方

| 文件 | 改动 | 量级 |
|---|---|---|
| `Gmeek.py` `createPostHtml` | 按 `##` 切分 `post_body`，循环渲染多份 HTML | 中 |
| `Gmeek.py` `addOnePostJson` | 记录章节列表供模板渲染导航 | 小 |
| `Gmeek.py` `createFileName` | 章节 URL 命名（复用现有 pinyin） | 小 |
| `templates/post.html` | 新增章节导航块、目录块 | 中 |
| `templates/chapter.html` | 新增章节页模板（或复用 post.html 分支） | 中 |
| `journal-style.css` | 章节导航样式 | 小 |
| 索引/标签/RSS | postUrl 指向第一章，链接不能断 | 小 |

### 难点（必须提前知道）

1. **切分必须在 HTML 之后做，不能在 Markdown 之前做。** 因为 GitHub Markdown API 要一次拿到整篇文章才能正确处理代码块、表格的跨段语义。按 `</h2>` 切已渲染的 HTML 是安全的；按 Markdown 的 `##` 切会误伤代码块里的 `##`。

2. **切分点仍会踩坑**：`<h2>` 可能在 `<blockquote>` 或 `<div>` 内部（GitHub Alert 里写标题），需要按 DOM 层级而非正则切。用 Python 的 HTML 解析器（`html.parser` 或 `lxml`）遍历顶层节点最稳。

3. **`page-break` 语义变化**：之前的分页引擎删了，但这次是构建层拆分，与 CSS 多栏无关，不会冲突。

4. **锚点链接会失效**：原文章内部的 `#某标题` 跳转在拆分后要跨页。需要在生成时把跨章锚点重写为绝对 URL。

5. **RSS/搜索/标签**：`postListJson` 的 `postUrl` 只能指向一个入口，通常选第一章。

### 工作量估计

- 代码：约 200–300 行 Python + 模板改动
- 测试：新增切分逻辑的单元测试（给定 HTML，断言切出正确章节数）
- 验证：需要跑一次完整构建，检查所有历史文章是否兼容
- 风险：**中高**。会影响所有文章的 URL（如果改 URL 结构），或只影响启用该功能的文章（更安全）

### 关键决策点

是否**所有文章**都拆，还是**只在标签/元信息里声明 `chapters` 的文章**才拆？
建议后者——存量 33 篇文章不动，新文按需启用。这能把风险从「全站」收窄到「单篇」。

### 效果

内容都在同一 HTML，但视觉上切成一张张固定高度的纸页卡片，像 PDF 翻页。

### 需要改的地方

| 文件 | 改动 | 量级 |
|---|---|---|
| `journal-paginate.js` | **重新创建一个**（这次删掉的那个） | 大 |
| `journal-style.css` | 恢复纸页容器样式 | 中 |

### 难点

这就是上一轮删掉的东西。本质问题没变：

1. **固定页高与可变内容冲突**。780px 装不下就溢出，要么裁切（丢内容）要么翻页（留白）。这是数学问题，不是实现技巧。
2. **块不可跨页 vs 段落必须跨页**。真实论文里段落会在页与页之间断开，而以块为单位分配必然禁止这件事。
3. **CSS 常量双写**。页高在 JS 和 CSS 各写一份，改一处要同步另一处。
4. **历史包袱**：上一轮 8 个连续 `fix(paginate)` 提交就是走这条路的结果。

### 工作量估计

- 代码：约 300 行 JS（相当于重写已删除的引擎）
- 风险：**高**。已知会重蹈覆辙。

### 唯一可能成立的变体

如果不追求「固定高度」，而是**按章切成等高卡片**（CSS `break-inside` + 视觉分组，不切裁），那就退化成方案 C 的视觉效果增强版，不需要 JS。但这就不叫「分页」了。

# 补充：PDF 式多页方案已验证可行（2026-10-29）

用户明确要求「实现类似 PDF 的多页」。已用 headless Chrome 完成算法原型并全量验证。

## 关键突破：DOM 顺序分页，不是高度计算分页

上次失败的根因是「测量块高 + 贪心分配 + 固定页高渲染」三件耦合。
本次改用 **DOM 顺序分页**：把块逐个 append 进当前页，每次 append 后检查是否有块
的 `bottom` 超过页面内容底边；溢出就把这一块整个挪到下一页开头。

```js
function paginate(host, raw) {
  var src = document.createElement('div'); src.innerHTML = raw;
  var nodes = Array.prototype.slice.call(src.children);
  var cur = newPage();
  nodes.forEach(function (node) {
    cur.appendChild(node);
    if (overflowed(cur)) {          // 检查最后一个块的 bottom 是否超过 limit
      cur.removeChild(node);        // 移出
      if (页空) cur.appendChild(node);   // 单块超过一页时硬放，不丢内容
      else { cur = newPage(); cur.appendChild(node); }
    }
  });
}
```

**为什么这次能成**：不预先计算总页数，不分配块到页，只是「边排边测」。
浏览器负责所有断行，JS 只判断「这块放得下吗」。块永远不会丢——因为只有
判断为溢出才移动，且单块超页时强制保留。

| 指标 | 结果 |
|---|---|
| 内容完整性 | **33/33 篇零丢失**（DOM 逐节点比对） |
| 页数范围 | 1–9 页，与文章长度线性对应 |
| 性能 | 7–16ms/篇，平均 7ms |

## 与 PDF 行为的差异（必须知道）

PDF 里句子可以在页与页之间断开（第 2 页开头续第 1 页末句）。
本方案的分配单位是**顶层块**（p / pre / table / h2…），块不可跨页。
所以段落会在页边界整体移到下一页，页脚可能有少量留白。

**这是刻意的取舍**：允许块跨页需要把段落拆成行级碎片再重新拼装，
复杂度和出错率会急剧上升（上次 8 个 fix 就是这个方向）。
当前方案保证「绝不丢内容 + 绝不重复」，代价是页脚偶有留白。

若必须做到句子跨页，唯一可靠的路径是 CSS `break-inside: auto` +
固定高度容器 + `column-fill: auto`，让浏览器自己决定在哪断行——
但那会回到「内容被 overflow:hidden 裁掉却无感知」的老问题。

## 实现落点

| 文件 | 改动 |
|---|---|
| `journal-paginate.js` | **新建**（约 120 行）。DOM 顺序分页 + 页码 + 移动端跳过 |
| `journal-style.css` | 新增 `.jpages` / `.jpage` 纸页容器样式（页高 780px、双栏、overflow:hidden） |
| `templates/post.html` | 无需改动（`#postBody` 保持，由 JS 接管） |
| `Earth/config.json` | `script` 字段加回 `journal-paginate.js` |

## 必须处理的边界

1. **移动端**：`window.innerWidth <= 720` 时不分页，保持单栏连续滚动。
2. **异步内容**：Mermaid / 图片加载会改变块高 → 等 `window.load` 后再分页。
3. **图片跨栏**：`p:has(img)` 仍保持 `column-span: all`，否则图文被栏线切开。
4. **宽块**：`pre` / `table` 设 `break-inside: avoid`，避免代码被切成两半。
